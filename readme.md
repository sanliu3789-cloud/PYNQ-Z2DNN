# 批量8条FPGA候选核：电脑端验收完成

日期：2026-10-30。所有构建和验证在电脑完成，本轮没有访问板卡、上传文件或加载硬件；现有CPU网页及原硬件设计未改动。

## 本轮解决的问题

原FPGA核每次只接收62个float输入并返回1个结果。原worker的“最多8条”是循环8次启动硬件、拷贝和维护缓存，并非一次启动的硬件批处理。

新候选核一次接收1至8条输入，只启动一次；各条数据复用同一计算核，保持原定点运算。它减少主机控制交互，不是8个并行计算核。

4条完整排列路径的解释共有252条扰动输入，硬件启动次数可从252次减少到32次，最后一批4条。这是控制次数变化，不代表实测加速倍数。

## 验证结果

| 检查 | 结果 |
|---|---|
| 权重与偏置 | 与现有低秩模型逐项量化比对通过，权重无裁剪 |
| Sigmoid表 | 4097项逐项比对通过 |
| C仿真 | 32组合成探针；76项批量/单条输出逐位一致；有效条数1至8均覆盖 |
| RTL协同仿真 | 1、3、4、8条及非法0、9条通过；16项有效输出逐位一致 |

数值门限0.01仅用于工程回归，不是临床可接受误差的标准。合成探针只使用既有均值、标准差和范围；没有读取患者记录，也没有评估独立预测准确率。

## 工程交付与运行要求

- artifacts/nihss_lowrank_batch8.bit、.hwh：本机完成布局布线后生成的批量核产物。
- artifacts/component.xml及xnihss_lowrank_batch8_hw.h：寄存器定义；本版HWH未列出这些HLS寄存器，应以导出的IP-XACT/驱动定义为准。
- reports/verification.json：验证、时序、寄存器和文件哈希。
- fixtures/fixture.json：固定种子和32组合成输入；test_plan.json：公平对照规程。
- 原来的标量worker与新核寄存器不兼容。独立批量worker见runtime/README.md；上板仍须满足稳定独立供电、重启复核和温度门控，再按1条、4条、8条逐步验证。
- 本候选没有RGB显示模块，不能直接驱动现有屏幕。

寄存器偏移：CTRL=0x00、ap_return=0x10、x=0x18、y=0x20、count=0x28。count仅允许1至8；非法条数返回1且不修改输出，有效调用返回0。

## 复现

在本目录执行，日志与生成项目均留在本目录：

```powershell
python -B prepare.py
python -B pc_compare.py
./run_build.ps1 *> verification_console.txt
python -B analyze.py
./build_implementation.ps1 *> implementation_console.txt
python -B analyze.py
python -B make_report.py
```

Vivado/HLS 2018.3使用临时R盘ASCII路径，脚本拒绝占用现有R盘并在结束后移除自己的映射。每次综合使用新的生成目录。旧工具的日期revision修正仅作用于生成的IP打包Tcl，不修改工具安装或系统日期。
